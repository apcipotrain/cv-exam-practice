# 第二题需求与实现方案

## 1. 任务理解

本题不是从一张俯视图“真实复原”校园正视图，也不是训练一个模型生成照片级结果。

更合理的建模目标是：根据给定校园俯视图、预览图和手绘路线，搭建一个仿真风格的简化 3D 校园场景，并沿路线生成三视图同步无人机视频。

及格示例显示，场景可以是低多边形/白模风格：

- 建筑使用简单盒体或挤出体块；
- 道路使用灰色平面；
- 水域使用蓝色平面；
- 树木使用简化几何体；
- 主无人机和伴飞无人机使用可辨认方向的简化模型；
- BEV 使用题目给定 preview 图作为底图，并叠加路线、当前位置和视锥。

核心不是照片级真实，而是满足“真实 3D 场景、同步相机、正确视频布局、路线和 BEV 对齐”的验收合同。

## 2. 输入材料

题目输入位于：

```text
题目2-release-pdf/
  题目.pdf
  自评表.txt
  input/
    route_ref.png
    tju_overview_60000x40000_4x4_q92.jpg
    tju_overview_60k_4x4_preview_3000x2000.png
  及格效果例子/
    1.png
    2.png
```

其中：

- `tju_overview_60000x40000_4x4_q92.jpg` 是超高分辨率俯视图，尺寸为 `60000 x 40000`，不能直接整图读入内存；
- `tju_overview_60k_4x4_preview_3000x2000.png` 是轻量预览图，尺寸为 `3000 x 2000`，适合路线提取、BEV 底图、人工标注和快速调试；
- `route_ref.png` 与 preview 图像素对齐，用于提取或人工校正飞行路线；
- 高分辨率 JPG 主要作为细节参考，主流程优先使用 preview。

## 3. 最终提交要求

最终只提交一个 `.tar` 文件。解包后的结构必须为：

```text
<名字>-<学校>/
  video.mp4
  自评表.txt
  readme.txt
```

顶层文件夹内只能有这三个文件。

`video.mp4` 必须满足：

- MP4 容器；
- H.264/AVC 编码；
- 帧率不低于 30 fps；
- 文件大小不超过 100 MB；
- VLC 可以正常播放和拖动；
- 每帧严格为 `2400 x 800`；
- 三个 `800 x 800` 视图从左到右拼接：

```text
PRIMARY | COMPANION | BEV
```

## 4. 三视图要求

### 4.1 PRIMARY 主视图

- 主无人机从路线无箭头端飞到箭头端；
- 高度参考值为 50 m；
- 相机朝向当前前进方向；
- 俯角 45 度；
- 水平/垂直 FoV 均为 90 度；
- 滚转角为 0 度；
- 位置和朝向应连续平滑，不能瞬移或突然转向。

### 4.2 COMPANION 伴飞视图

- 伴飞无人机大致与主无人机同高；
- 参考位置在主无人机前进方向后方约 20 m；
- 相机朝向主无人机当前前进方向，且应能看到主无人机；
- 俯角 15 度；
- 水平/垂直 FoV 均为 90 度；
- 滚转角为 0 度；
- 至少 90% 视频时间内应能看到主无人机，并能判断其位置和朝向。

### 4.3 BEV 俯视视图

- 底图必须使用 `tju_overview_60k_4x4_preview_3000x2000.png`；
- 将底图按原始比例缩放到宽 800；
- 高度约为 533 或 534；
- 放入 `800 x 800` 黑色面板，上下居中；
- 不得裁剪，不得非等比拉伸；
- 叠加主无人机完整轨迹、伴飞无人机完整轨迹、当前位置和视锥。

## 5. 推荐实现路线

本项目采用“程序化低模 3D 场景 + OpenCV 拼接视频”的方式实现。

推荐流程：

1. 数据检查：确认输入图片尺寸、路线图与 preview 是否对齐；
2. 路线提取：从 `route_ref.png` 中提取手绘路线，生成像素坐标折线；
3. 路线平滑：将折线重采样并平滑，得到连续轨迹；
4. 米制标定：根据公开地图或已知距离估算像素到米的比例；
5. 场景建模：用 preview 图或人工标注生成道路、水域、主要建筑、树木；
6. 3D 构建：将建筑轮廓挤出成非零高度体块，生成简化校园场景；
7. 相机轨迹：根据路线生成主无人机和伴飞无人机的位置、朝向；
8. 渲染视图：从同一 3D 场景同步渲染 PRIMARY 和 COMPANION；
9. BEV 合成：用 preview 底图绘制路线、无人机位置和视锥；
10. 视频拼接：把三视图拼成 `2400 x 800` 的 `video.mp4`；
11. 自测交付：填写 `自评表.txt` 和 `readme.txt`，打包为 `.tar`。

## 7. 第一阶段目标

开始写 3D 场景之前，先完成路线和 BEV 验证。

第一阶段应产出：

- 输入图片尺寸检查结果；
- 从 `route_ref.png` 提取出的路线点；
- `outputs/route_debug/route_overlay.png`：路线叠加在 preview 图上的检查图；
- `outputs/route_debug/bev_sample.png`：800 x 800 BEV 面板样例；
- `data/annotations/route_points.json`：后续 3D 飞行轨迹使用的路线点。

只要 BEV 路线正确，后续 3D 场景和相机动画才有可靠锚点。

## 8. 风险与策略

### 风险 1：超大 JPG 爆内存

不要直接读取 `60000 x 40000` 大图。主流程使用 `3000 x 2000` preview，高分图只做局部参考。

### 风险 2：建筑真实度不够

及格示例允许白模/低多边形风格。优先保证主要建筑位置、轮廓和高度存在，而不是追求真实立面纹理。

### 风险 3：伴飞视图看不到主无人机

主无人机模型要有明显方向标记，伴飞相机要持续朝向主无人机附近，可适当偏离严格 20 m 后方位置以保证可见性。

### 风险 4：输出合同错误

必须严格检查视频尺寸、编码、帧率、文件大小、tar 结构、两个 txt 是否 UTF-8 且内容完整。

## 9. 及格优先级

按重要性排序：

1. 输出结构正确；
2. 视频尺寸、编码、帧率正确；
3. 三视图同步；
4. PRIMARY 完整沿路线飞行；
5. COMPANION 能看到主无人机；
6. BEV 使用 preview 底图且路线对齐；
7. 主要建筑有三维体量；
8. 视觉细节更丰富。

先满足 1-7，再考虑视觉美化。
