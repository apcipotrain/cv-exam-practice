# 照片抽象建模模块说明

## 1. 当前采用的最终方向

题目要求的 PRIMARY 和 COMPANION 不是航拍图裁片，也不是把卫星图强行透视。

正确理解应是：

```text
航拍图 / JPG / route_ref
        ↓
提取路线、建筑、水体、道路、树木等空间线索
        ↓
抽象成低多边形 3D 校园
        ↓
从无人机相机渲染 PRIMARY / COMPANION
```

因此最终使用 `10_render_abstract_scene.py`，而不是 `07_render_from_frame_contexts.py`。

## 2. 各模块职责

- `06_export_frame_contexts.py`  
  逐帧输出高清 JPG 局部图块和环境表，用于判断路线周围是什么。

- `08_refine_route_away_from_black.py`  
  根据图像边界修正路线，避免飞到黑色无效区域。

- `09_refine_route_to_roads.py`  
  实验性道路吸附模块。当前结果有过度吸附和锯齿，因此不作为最终路线。

- `10_render_abstract_scene.py`  
  最终抽象渲染模块。它使用修正后的路线和人工/视觉参考得到的场景布局，渲染低模校园视频。

## 3. 为什么不直接用照片贴图

直接使用高清 JPG 裁片会导致：

- PRIMARY 看起来仍像俯视地图；
- COMPANION 不像真实伴飞相机；
- 不满足题目中“真实 3D 场景/仿真”的预期；
- 与及格例子的低模校园风格不一致。

所以照片应该用于“理解和抽象”，而不是直接作为主视图画面。

## 4. 最终视频应满足的视觉特征

- 建筑是有高度的块体；
- 道路是灰色连续平面/线；
- 水体是蓝色平面；
- 树木是重复的简化几何体；
- PRIMARY 是沿路线前进的斜视角；
- COMPANION 能看到主无人机模型；
- BEV 使用原始俯视底图和路线叠加。
