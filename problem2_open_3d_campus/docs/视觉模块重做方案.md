# 视觉模块重做方案

## 1. 为什么要推翻旧模块

旧版 `03_render_video.py` 主要依赖人工手写的道路、建筑、树木和水体，因此会出现：

- 道路与真实 JPG 不一致；
- 建筑位置不准；
- 树木、草地、水体混在一起；
- 路段附近的场景看起来像在“移动”或“漂浮”；
- 终点附近场景过空。

所以新方案不再从想象中手写场景，而是沿飞行路径局部读取高清 JPG，再从图像中提取场景元素。

## 2. 核心建模思想

采用“沿路线局部视觉理解”的方法：

```text
route_points.json
        ↓
2000 帧路线采样
        ↓
沿路线切割高清 JPG 局部图块
        ↓
识别道路 / 建筑 / 树林 / 草地 / 水体
        ↓
合并为 scene_annotations.json
        ↓
3D 渲染器读取真实图像识别结果建模
```

这样做的好处是：只关心无人机实际飞过和看到的区域，不需要一次性理解整张 60000x40000 大图。

## 3. 高清 JPG 与 preview 的关系

题目给了：

- `tju_overview_60k_4x4_preview_3000x2000.png`
- `tju_overview_60000x40000_4x4_q92.jpg`

两者比例一致：

```text
60000 / 3000 = 20
40000 / 2000 = 20
```

所以 preview 上的一个点 `(x, y)`，对应高清 JPG 上大约是：

```text
(x * 20, y * 20)
```

新模块可以先用 preview 定位，再到高清 JPG 里切对应局部区域。

## 4. 分类规则

### 4.1 树林

树通常表现为：

- 绿色；
- 一坨一坨、不连续；
- 纹理变化大；
- 有较强局部阴影和颗粒感。

判断方式：

- 绿色指数高；
- 局部方差高；
- 连通域面积中等或较小；
- 可以转成树点或树簇。

### 4.2 草地

草地通常表现为：

- 绿色；
- 连续大片；
- 纹理比树更平滑；
- 连通域面积大。

判断方式：

- 绿色指数高；
- 局部方差较低；
- 连通域面积大；
- 建模为低高度平面。

### 4.3 江面 / 湖面

水面在这张图中不是蓝色，而是比较均匀的暗绿或灰绿。

判断方式：

- 颜色偏绿灰；
- 饱和度中低；
- 局部纹理很平滑；
- 形状连续、边界弯曲。

建模时转成蓝绿色平面。

### 4.4 道路

道路通常表现为：

- 灰色或浅灰色；
- 呈细长连续结构；
- 沿路线附近出现；
- 边界较规则。

判断方式：

- 饱和度低；
- 明度中高；
- 形状细长；
- 与路线方向一致。

### 4.5 建筑

建筑通常表现为：

- 屋顶灰白、蓝灰、红棕；
- 边缘直线明显；
- 形状近似矩形、多边形或圆形；
- 纹理比道路更块状。

特殊注意：起点前方有一个明显圆形建筑，应单独识别或作为强先验加入。

## 5. 输出内容

新视觉模块输出：

```text
outputs/scene_extract/
  scene_annotations.json
  scene_overlay_preview.png
  masks/
    road_mask.png
    building_mask.png
    tree_mask.png
    grass_mask.png
    water_mask.png
  tiles/
    segment_*.png
```

`scene_annotations.json` 是后续 3D 渲染的核心输入。

## 6. 当前阶段目标

第一阶段不追求完美，只做可验证的视觉中间结果：

1. 能沿路线切图；
2. 能把水体、道路、建筑、树/草粗分出来；
3. 能生成叠加检查图；
4. 暂时不渲染视频。

等中间结果确认后，再把它接回 `03_render_video.py`。
